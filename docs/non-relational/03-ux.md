# 03 — UX & Interaction Design: Multi-Paradigm Terminal Navigation

## 1. UX Principles

1. **Keyboard First**: Every navigation, query, inspection, detail view, and export operation has a dedicated keyboard shortcut.
2. **Single-Window Layout**: Header, Sidebar, Main Pane, Editor, and Footer remain always visible and synchronized.
3. **Adaptive Panes**: Pane titles, content layout, detail views, and structure views adapt to the semantic shape of the selected engine.
4. **Predictable Keymaps**: Global shortcuts (`Tab`, `Alt+1..3`, `Alt+B`, `Alt+E`, `Ctrl+R`, `Ctrl+N`, `Ctrl+P`, `?`, `q`) behave consistently across all engines.

```
│ HEADER (1 line)                                             │
│ picklock [ mongodb://localhost:27017/test ] [ users ]           │
├──────────────┬──────────────────────────────────────────────┤
│              │ MAIN PANE (Browser / Structure / Detail)     │
│  SIDEBAR     │ - Relational: Columns × Rows                 │
│  (Catalog)   │ - Document: JSON Document list               │
│  ~1/4 width  │ - Key-Value: Header + Key entries table      │
│              │ - Graph: Node list + Incident edges          │
│              ├──────────────────────────────────────────────┤
│              │ QUERY EDITOR (Input + Results)               │
│              │ ~1/3 height (SQL, MQL, Redis, CQL, Cypher)   │
├──────────────┴──────────────────────────────────────────────┤
│ FOOTER (1 line)                                             │
│ [contextual shortcuts]                     [page / count]   │
└─────────────────────────────────────────────────────────────┘
```

### Dynamic Sidebar Titles & Item Nouns

| Engine | Sidebar Title | Item Noun | Sample Items |
|---|---|---|---|
| SQLite, Postgres, MySQL, MariaDB, MSSQL | `TABLES` | table | `users`, `orders`, `products` |
| MongoDB | `COLLECTIONS` | collection | `accounts`, `events`, `profiles` |
| Redis | `KEYS` | key | `user:1000` `[hash]`, `queue:jobs` `[list]`, `tags` `[set]` |
| Cassandra | `TABLES` | table | `user_timeline`, `sensor_readings` |
| Neo4j | `LABELS` | label | `(:User)`, `(:Product)`, `[:PURCHASED]` |

## 3. Main Pane Rendering by Paradigm

### 1. Relational & Wide-Column (Tabular View)
```
 id | name        | email              | created_at
----+-------------+--------------------+---------------------------
  1 | Alice Smith | alice@example.com  | 2026-08-01 10:15:00
  2 | Bob Jones   | bob@example.com    | 2026-08-01 11:20:00
```

### 2. Document View (MongoDB)
```
 > [64a1f8...] name: "Alice", email: "alice@example.com", roles: ["admin", "dev"]
   [64a1f9...] name: "Bob", email: "bob@example.com", status: "pending"
   [64a1fa...] name: "Carol", email: "carol@example.com", balance: 1450.50
```

### 3. Key-Value View (Redis)
When browsing a key `user:1000` (Hash):
```
 Key: user:1000 · Type: hash · TTL: 847s · Memory: 216B
------------------------------------------------------------
 FIELD              | VALUE
--------------------+---------------------------------------
 name               | Alice Smith
 email              | alice@example.com
 login_count        | 42
```
When browsing a key `queue:jobs` (List):
```
 Key: queue:jobs · Type: list · TTL: -1 · Length: 3
------------------------------------------------------------
 INDEX              | VALUE
--------------------+---------------------------------------
 0                  | {"task": "send_email", "id": 101}
 1                  | {"task": "generate_report", "id": 102}
```

### 4. Graph View (Neo4j)
When browsing Node Label `(:User)`:
```
 > (:User #12) name: "Alice", email: "alice@example.com"  [2 edges]
   (:User #13) name: "Bob", email: "bob@example.com"      [1 edge]
```

## 4. Detail View (`v` Key)

Pressing `v` opens the full, non-truncated detail view:
- **Relational / Cassandra**: All columns with full values wrapped to the viewport.
- **MongoDB**: Indented, pretty-printed JSON document:
  ```json
  {
    "_id": "64a1f8...",
    "name": "Alice Smith",
    "email": "alice@example.com",
    "profile": {
      "age": 24,
      "timezone": "America/New_York"
    },
    "roles": [
      "admin",
      "developer"
    ]
  }
  ```
- **Neo4j**: Node properties + interactive relationship tree:
  ```text
  Node #12 (:User)
  ==============================================
  Properties:
    name: Alice Smith
    email: alice@example.com
    age: 24

  Relationships:
    -> PURCHASED -> (:Product #42, title: "Laptop")
    -> OWNS      -> (:Order #991, total: 1200)
    <- INVITED_BY<- (:User #8, name: "Charlie")
  ```

## 5. Structure View (`i` Key)

Pressing `i` switches the main pane to the structural inspector:
- **Relational**: Columns (Name, Type, `PK`, `NN`, `DEF`) + Indexes (`UNIQUE`).
- **Cassandra**: Columns with explicit `PK` (Partition Key), `CC` (Clustering Column), CQL types (`uuid`, `list<text>`, `map<text, int>`) + Indexes.
- **MongoDB**: Collection stats (Document count, Storage size, Avg object size, Index size) + Index definitions + Inferred top-level field types.
- **Redis**: Key metadata (Type, TTL, Object encoding, Memory usage, Key length) + Server overview stats.
- **Neo4j**: Node property definitions, data types, unique constraints, index definitions, and connecting relationship types.

---

## 6. Query & Command Editor

The bottom editor pane adapts its title and placeholder:
- **Relational**: `SQL EDITOR` — multiline SQL with line-based semicolon statement execution (`Ctrl+R`).
- **MongoDB**: `MONGO QUERY` — executes JSON filter queries `{"status": "active"}` or pipelines.
- **Redis**: `REDIS COMMAND` — executes Redis commands (`GET key`, `HGETALL key`, `INFO`, `SCAN 0`).
- **Cassandra**: `CQL EDITOR` — executes CQL queries.
- **Neo4j**: `CYPHER EDITOR` — executes Cypher queries (`MATCH (n:User) RETURN n`).

Results from the editor render in the lower half according to their semantic `DataView` (tabular results, document lists, key-value entries, or status banners).
