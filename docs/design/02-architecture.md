## Layers and responsibilities

### `cmd/picklock/main.go`

- Launches `tui.New()` and `bubbletea.Program.Run()`.
- Handles the exit error with an appropriate exit code.
- Contains no business logic. Does not open connections: that is done by the connection screen inside the TUI.

### `internal/conn`

Describes **what** we connect to, without knowing how to connect:

```go
type ConnectionConfig struct {
    Driver string // sqlite | postgres | mysql | mariadb | mssql
    Name   string // name to save the connection with

    // SQLite
    Path string
    // Opens SQLite in read-only mode (mode=ro). Prevents accidental writes.
    ReadOnly bool

    // Network (postgres, mysql, mariadb, mssql)
    Host     string
    Port     int
    User     string
    Password string
    Database string
    // PostgreSQL TLS (prefer | require | verify-full | disable). Empty = prefer.
    SSLMode string
}
```

Rule: `ConnectionConfig` is the only way a connection enters the system. `store.New()` receives a `ConnectionConfig` and returns the correct `Store`.

> **SPEC deviation:** `conn` is pure (no dependency on TUI components). The connection form state lives in `internal/tui/screens/connect.go` as `ConnScreen`, and `conn` only provides the data and persistence (`saved.go`).

### `internal/store`

**The most important layer of the design.** Defines the `Store` interface:

```go
type Store interface {
    // Connection
    Driver() string
    Version() (string, error)
    Close() error

    Tables() ([]string, error)
    Columns(table string) ([]Column, error)
    Indexes(table string) ([]Index, error)
    ForeignKeysContext(ctx context.Context) ([]ForeignKey, error)
    // Arbitrary execution
    Query(sql string) (*Result, error)
    Exec(sql string) (int64, error)          // rowsAffected

    // Dialect: pagination and counting generated by the engine
    CountTable(table string) (int, error)
    SelectTablePage(table string, limit, offset int) (*Result, error)
}
```

Custom data types:

```go
type Column struct {
    Name    string
    Type    string
    NotNull bool
    Default string
    PK      bool
}

type ForeignKey struct {
    Name              string
    TableSchema       string
    Table             string
    Columns           []string
    ReferencedSchema  string
    ReferencedTable   string
    ReferencedColumns []string
    UpdateRule        string
    DeleteRule        string
}

type Result struct {
    Columns []string
    Rows    [][]string   // Everything is a string. The UI formats.
    Count   int
    Affected int64       // rows affected by an Exec; -1 if not applicable (read)
    Nulls   [][]bool     // mirrors Rows: true where the cell was SQL NULL
}

type Index struct {
    Name    string
    Columns []string
    Unique  bool
}
```

- `Affected` distinguishes a "table" (read queries, non-empty `Columns`, `Affected == -1`) from "N rows affected" (INSERT/UPDATE/DELETE). The UI decides how to display based on `Result`, never re-parsing SQL.
- `ScanResult` (`scan.go`) converts `database/sql.Rows` into `*Result`; it is used by all engines.

**Rule:** no other layer imports `database/sql` or drivers directly. Everything goes through `Store`. The TUI, browser, and editor don't know which engine they are talking to.

### Dialects (`internal/store/<engine>/dialect.go`)

Each engine knows its own SQL. The UI never sees differences:

```go
type Dialect struct {
    QuoteIdent func(ident string) string      // "x" | `x` | [x]
    Limit      func(limit, offset int) string // LIMIT n OFFSET m | OFFSET m ROWS FETCH NEXT n ROWS ONLY
}
```

- **SQLite and PostgreSQL:** `"ident"`, `ORDER BY 1 LIMIT n OFFSET m`.
- **MySQL and MariaDB:** `` `ident` ``, `ORDER BY 1 LIMIT n OFFSET m`.
- **SQL Server:** `[ident]`, `ORDER BY 1 OFFSET m ROWS FETCH NEXT n ROWS ONLY`.

The `ORDER BY 1` (first column) makes the browser pagination stable; it is the
same heuristic SQL Server already required for `OFFSET/FETCH`.

Introspection (tables, columns, indexes, version) also lives in the engine's dialect:

| Engine | Schema source |
|---|---|
| SQLite | `sqlite_master` + `PRAGMA` |
| PostgreSQL | `information_schema` + `pg_indexes` |
| MySQL / MariaDB | `information_schema` |
| SQL Server | `INFORMATION_SCHEMA` + `sys.indexes` |

`LIMIT n OFFSET m` with integers is safe for direct interpolation (it is not user input). Identifiers are ALWAYS escaped with `QuoteIdent`, including the active table.

### Engine registration (`internal/store/store.go`)

Each engine registers itself in its `init()`, and `store.New(cfg)` looks it up in the registry.
`store` does not import the engines → no import cycles.

```go
// store.go
func Register(d conn.Driver, c Constructor)
func New(cfg conn.ConnectionConfig) (Store, error)

// sqlite/store.go, postgres/store.go, ...
func init() { store.Register(conn.DriverSQLite, func(cfg conn.ConnectionConfig) (store.Store, error) { return New(cfg) }) }
```

- `mysql.NewMySQL` and `mysql.NewMariaDB` share the implementation; they differ in `Version()` and in introspection details where MariaDB diverges.
- An unknown driver returns `ErrUnsupportedDriver`.
- `cmd/picklock/main.go` blank-imports the 4 engine packages (`_ ".../store/mysql"`, etc.) so they register themselves.

### `internal/browser`

Manages the **navigation state**:

```go
type Browser struct {
    Tables      []string
    ActiveTable string
    Columns     []Column
    Page        int
    PageSize    int    // default: 50
    TotalRows   int
    Rows        [][]string
    Cursor      int    // row selected on screen
}
```

Methods:
- `Load(store Store) error` — loads available tables.
- `SelectTable(name string, store Store) error` — switches active table, resets page.
- `NextPage / PrevPage(store Store) error` — navigates pages. The page query is generated by the store (`SelectTablePage`), because the dialect belongs to the engine.
- `Refresh(store Store) error` — reloads data from the active table.

It knows nothing about the TUI or rendering.

### `internal/editor`

Manages the **SQL editor state**:

```go
type Editor struct {
    Buffer   string       // current input content
    History  *History     // ring buffer
    Result   *store.Result
    Error    string
    Mode     EditorMode   // Normal | Executing
}
```

Methods:
- `Execute(store Store) error`
- `PrevHistory() / NextHistory()`
- `Clear()`

### `internal/export`

Thin serializers over an in-memory `store.Result`: `WriteCSV` (RFC 4180,
`encoding/csv`) and `WriteJSON` (array of objects in column order, NULL →
`null` via `Result.Nulls`, HTML escaping disabled). It never touches a
database or a driver. The TUI collects the data (`editor.Result` or the
browser's current page) and calls it from the `Alt+E` prompt.

### `internal/tui`

Implements the bubbletea loop. `app.go` holds the main `Model`:

```go
type Model struct {
    store   store.Store
    connect *screens.ConnScreen // connection form
    browser *browser.Browser
    editor  *editor.Editor
    screen  Screen              // ScreenConnect | ScreenWorkspace
    focus   screens.WorkspaceFocus // FocusSidebar | FocusMain | FocusEditor
    structure bool              // the main pane shows the table structure
    sidebarCursor int           // table selected in the sidebar
    exporting bool              // the Alt+E export prompt is open
    showDetail bool             // the row detail view is open
    width   int
    height  int
    keys    KeyMap
}
```

The workspace is a **single window** with three panes (sidebar, main, editor).
`Update()` dispatches keys to the focused pane; `View()` renders the panes via
`screens.RenderWorkspace`.

**Rule:** all business logic lives in `browser`, `editor`, or `conn`. The TUI only translates keys into actions and calls methods.

## Data flow

```
main.go
  └─ creates tui.Model (without store)
       └─ bubbletea.Program.Run()
            ├─ ScreenConnect: user fills in the form → connectMsg
            │    └─ Update() → store.New(cfg) → browser.New(store) → ScreenWorkspace
            ├─ KeyMsg (sidebar) → browser.SelectTable(table) → store.Columns/Indexes/Page
            ├─ KeyMsg (main)    → browser.NextPage() → store.SelectTablePage()
            ├─ KeyMsg (editor)  → goroutine → editor.ExecuteAt() → store.Query()/Exec()
            │    └─ editorDoneMsg → update editor; if write query → browser.Reload(store)
            └─ WindowSizeMsg → adjusts width/height
```

`Ctrl+N` (new connection) closes the current store, resets browser/editor, and returns to `ScreenConnect`.

## Design decisions that do NOT change

- `Result.Rows` is `[][]string`. Every cell is converted to a string in the store. The UI makes no type assertions.
- No layer outside `internal/store/**` imports `database/sql` or a driver.
- There is no global state. All state lives in the bubbletea `Model`.
- **A single extra goroutine:** the editor's query execution runs in the background (so slow queries don't freeze the event loop, and a spinner can be shown). The result travels in `editorDoneMsg` with a token (`queryID`) that discards stale results if the session changes. Everything else is synchronous.
- Query errors are shown on screen, not logged to a file.
